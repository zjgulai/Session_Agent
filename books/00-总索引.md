# 经验手册 · 总索引

> 从 5 个月、2,794 个 coding 会话（Codex / opencode / Claude）蒸馏出的可复用经验。
> 判据：问题类 × 收敛解；每条经验都过了双模型复现门。
> 隐私：全部抽象化，不含会话原文。

**👉 日常查阅请看 [速查单页.md](速查单页.md)**——三张决策图：选卡树 / 纪律时机 / 交付前红线。本文件是完整索引与分册入口。

## 怎么用这本手册

1. **遇到问题** → 先在下面的"问题类速查"里找对应类。
2. **找到卡** → 读该卡的"解决方案 + SOP"，直接照做。
3. **踩坑前** → 读该卡的"反例与坑"。
4. **想复制** → 抄"指令形状"，填槽即用。

> **卡 12–17 是六条纪律，分两组**：
> **证据组**（12–16）：别说过头（A ≠ B）· 别卡住（报阻塞+替代）· 别空口（带回查路径）· 别做漏（交付前自检）· 别装懂（标未知并移出）。
> **安全组**（17）：默认拒绝，只有明确通过才放行。

> **卡 12 是所有卡的共同底座。** 它说的是同一件事：**A ≠ B**。
> `已安装 ≠ 已认证` · `代码存在 ≠ 功能完成` · `测试绿 ≠ 风险关闭` · `草稿存在 ≠ 允许发送` · `环境限制 ≠ 产物缺陷`。
> 每张卡的核心句，本质上都是它的一种具体形式。

**合并类** = 语义聚类后的会话数（同义措辞已合并）。全量 support 明细（每步会话数与占比）见 [../05-support-全量.md](../05-support-全量.md)。

**不予发布**：
- **09 调试排障协议** —— 复现门两次未通过。核心句是脚手架（0/20）；真"报错→修复"会话仅 ~2/20。

## 三条元规则（比单张卡更重要）

1. **问题类用收敛模板找，不用关键词。** 你反复复用的固定句式（≥3 次）才是你验证过的协议。
2. **涌现 = 高频 且 不在配置语料里。** 配置语料（AGENTS.md / skills / agents）里的做法是脚手架，不是经验。
3. **每条结论都要过复现门。** 第二个模型独立抽同一批会话，一致才算过。它已多次纠正错误判断。

**完整元层**见 [元层-蒸馏方法.md](元层-蒸馏方法.md)：判据、三个关键区分（问题类 vs 技法 / 脚手架 vs 涌现 / 配置 vs 执行）、类判据设计、两道门、可复制流程、已证伪做法。

### 05 · 批次推进协议（本册核心）

**收敛解**：**批准 ≠ 直接执行。** 拆成：预检 → 批次推进 → 每批验收闭环 → 带证据收口。

**SOP**
1. **预检回执**：核分支、HEAD、工作区、前序阶段状态。
2. 按**批次**推进，不一次铺开。
3. 建 **RED 基线**：先复现当前失败，再动手。
4. 每批带**验收闭环**（跑指定验证）。
5. **独立审查门**：另一个 reviewer 复核，不自己盖章。
6. **提交卫生**：只暂存指定文件、单一提交、`diff --check`、staging 留空。
7. 带证据收口：状态标签、HEAD、严重度计数、已落地、**非动作清单**。
8. 未过门 → 标 BLOCKED，不假装推进。

**收口模板**
```
{批次} 已完成，状态 {Ready | DONE_WITH_CONCERNS | BLOCKED}。
已落地：{改动清单}。验证：{检查项 + 计数}。
独立审查：Critical {n} / Important {n} / Minor {n}。
最终 HEAD {sha}，本批 {k} 个提交。staging 为空。未做：{非动作清单}。
```

## 本册的方法论要点

- **批次粒度是控制面**：不一次铺开，每批必须收口才能开下一批。
- **独立审查是 done 的门**，不是可选动作；它失败会阻断完成宣告。
- **收口必须含非动作清单**：只说"做了什么"无法核验，必须说"没做什么"。

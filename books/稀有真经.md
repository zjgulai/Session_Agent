# 稀有真经

> 这些行为**覆盖率高不高**（1%–10%），但**样本极硬、极其具体**。
> 按元层判据：稀有真经 → **单列，不收卡**（凑不成协议，但值得记住）。
> 每条都附真实会话里的抽象化例证。

---

## 1. 反常信号不忽略，停下来查（2%）

**做法**：工具输出反常时，不绕过、不重试、不假设是噪声——先停下来确认，再继续。

**为什么值钱**：反常输出往往指向真实缺陷，但很容易被当成"工具怪癖"忽略。

**实例（抽象）**：
- `nl` 读某个 `.py` 显示成二进制，但 `python` 刚能正常运行 → 停下确认文件类型和 git 内容，避免在错误状态上继续编辑
- 几个 `.ts` 文件用 `nl` 读像二进制 → 不忽略这个信号，确认是工具误判还是文件有隐藏 NUL/二进制尾部
- 一个图表脚本定义了 8 个图表，但页面没有加载它 → 说明"趋势页"本质是表格，不是图表化报告

**判据**：同一事实，两个工具给出不同结果 → **必须查**。

---

## 2. 表面满足 vs 实质满足（1%）

**做法**：区分"形式上通过"和"实质上成立"。

**实例（抽象）**：
- 计划文档"看起来完整"，但漏掉实际落地入口 → 执行不了
- `184 个部署 agent 与源档案名称集合一致`，但仍有未提交的 `_PENDING_UPGRADES.md`、5 个命名违规、8 个悬空端点 → **看起来完整、实际上不可控**
- 配置里写着 `BUCKET_URI`，但值是 `<private-bucket-appid>` 占位符 → **看似已设置，实际是模板**
- 测试"看似通过"，但增量入口没有状态约束 → 假阳性

**判据**：通过的是**形式**，还是**形式背后的实质**？

---

## 3. 主动承认自己的操作失误（2%）

**做法**：发现自己做错了，**先恢复现场**，再说下一步。

**实例（抽象）**：
- 一次删除补丁因工具默认目录，落到了原始 checkout 而不是隔离 worktree → `这是我这边的操作失误；我会先把原始 checkout 恢复到只剩用户原本的未跟踪内容，再在隔离 worktree 里用绝对路径继续`
- 路径别名展开错了 → `我刚才路径别名展开错了，马上按实际技能路径补读`
- 远程 heredoc 引号被本地 shell 截断 → `没有改动服务器配置。我换成更稳的方式重新执行`

**判据**：错了就说是错的，**先恢复，再继续**，不悄悄抹掉。

---

## 4. 完成度诚实：说"只剩 X"（强表述 10%）

**做法**：不笼统说"完成了"，而是精确说出**还剩什么**。

**实例（抽象）**：
- `明确本轮部分完成状态和唯一剩余缺口，防止下次误重跑整个品类再次消耗额度`
- `当前只剩一件流程外事项：这些变更还在本地工作区，尚未 commit/push`
- `value-loop 只剩一个 marker 失败`
- `Build 通过，只剩一个既有的 deprecation warning，这次没有改它`

**判据**：**"只剩 X"** 是收口的黄金句式——比"基本完成"精确得多。

---

## 5. 拒绝默认做法（4%）

**做法**：不因为"有工具/有旧结论/有惯例"就直接采用。

**实例（抽象）**：
- 不用现成的 code review 工具，因为它只覆盖 diff/PR，而任务是全项目 → 手动静态诊断
- 不照单全收旧审计结论 → 先用当前代码和测试验证
- 不因为"目录里有这个名字"就当成可用能力 → 实际核验

**判据**：**默认路径**是否真的适配当前任务？

---

## 6. 纠正用户前提（0.2%）

**做法**：用户的前提本身不成立时，先指出，再继续。

**实例（抽象）**：
- 用户认为某字段缺失，实际是读取路径错了
- 用户描述的"乱码"，实际是 ANSI/TUI 控制码裸露，不是编码问题
- 用户假设的"部署已完成"，实际只完成了本地

**判据**：用户给的**前提**，是否也需要被验证？

---

## 这些为什么不出卡

| 原因 | 说明 |
|---|---|
| 覆盖率太低 | 1%–10%，凑不出稳定协议 |
| 样本太集中 | 多数来自少数几个项目，泛化性未证 |
| 形态是"提醒"不是"流程" | 一句话就能说完，不需要 SOP |

**但它们的价值在于**：当你遇到对应场景时，能想起"这里有个坑"。

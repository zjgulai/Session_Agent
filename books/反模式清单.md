## 1. 误判根因

**症状**：定位到"看起来最像"的地方就开始修，修完没好。

**真实例句**（抽象）：

| 以为是 | 实际是 |
|---|---|
| 日期控件有问题 | 数据合同混用了两类时间（采集窗口 vs 内容日期） |
| 代码回归 | 首次 smoke 少传了必需的环境变量 |
| 浏览器兼容性 | 服务器缺文件，Nginx fallback 把 HTML 当视频返回 |
| 终端显示问题 | JSONC 解析失败，配置文件有坏字节 |
| 模板问题 | 改 JSON 时漏了一个逗号 |
| 词太少 | 加载器根本没接入那份 JSON |

**为什么会犯**：症状出现在最显眼的地方，而原因在最不显眼的地方。

**怎么避免**：
- 先问"这个症状还能由什么产生"，列 2–3 个候选
- 用**排除法**验证：改一个变量，看症状是否消失
- **根因不是 X，而是 Y**——把这句话写出来，再去验证

**对应卡**：03 断点恢复（先验证）、09 调试排障（未发布）

## 2. 过度扩展

**症状**：用户要改 A，顺手把 B、C 也改了。

**真实例句**（抽象）：

```
不需要扩大到 fs-safety.mjs
不需要重构现有 stage 机
不需要公共 helper 重构
不需要扩大 prototype.css 改动范围
不应该继续扩展浏览器、Poyo、ECC 或历史插件；应先把自有核心做完
```

**为什么会犯**：模型倾向于"顺手优化"，把局部改动升级成架构改造。

**怎么避免**：
- 改动前写下"本次只碰哪些文件"
- 出现"顺便"念头时，把它变成独立任务，不夹带
- 用卡 18 的**范围边界**提前封死

**对应卡**：05 批次推进（最小改动）、18 边界指令

---

## 3. 重复劳动

**症状**：重跑已经跑过的测试、重新采集已经采过的数据。

**真实例句**（抽象）：

```
重复执行 full suite、build、quick gate
重复采集已经完成的 6 个来源
重复采集或遗漏结束日
```

**为什么会犯**：不知道已完成什么，或没读状态就开跑。

**怎么避免**：
- 开跑前先读状态（TODO / 断点 / 运行记录）
- 用卡 03 的**先验证断点**：确认哪些已完成
- 幂等：同一任务重复执行不应产生副作用

**对应卡**：03 断点恢复、05 批次推进

---

## 4. 过早动手

**症状**：还没确认清楚就开始改。

**真实例句**（抽象）：

```
未确认视觉效果就覆盖生产
应该先给出"品类不存在"的反馈，再考虑 live API 闸门
需要先修交互，再补页面使用说明
```

**为什么会犯**：任务看起来简单，跳过了"先看清"这一步。

**怎么避免**：
- 写代码前先回答："现在的行为是什么？期望是什么？差在哪？"
- 用卡 01 的只读审计先建立基线

**对应卡**：01 只读审计、02 项目诊断

## 5. 过度探索

**症状**：用户要结论，模型还在扫。

**真实例句**（抽象）：

```
停止继续探索，立即按已读内容返回逐项 closed/open
请停止任何仍在运行的验证进程，立即基于已完成审查返回最终结论
请立即停止扩展扫描，基于已读证据给出简洁最终审计结果
我必须要你快一些了，别钻进了小细节里
```

**为什么会犯**：模型把"做得更全"当成"做得更好"，但没有停止条件。

**怎么避免**：
- 用户侧：写卡 18 的**努力/深度上限**（`不要继续探索，直接给结论`）
- 模型侧：探索前先定"够了的标准"

**对应卡**：18 边界指令

---

## 6. 产物形态错

**症状**：要的是单页演示，给的是完整工程。

**真实例句**（抽象）：

```
我说的是演示 html，像昨天第一个业务一样，单 HTML 演示版
```

**为什么会犯**：没说清形态，模型默认给"完整版"。

**怎么避免**：
- 用户侧：明确产物形态（单页/工程/表格/报告）
- 模型侧：动手前先确认形态

**对应卡**：18 边界指令

---

## 7. 工具误用

**症状**：用了不该用的工具或进程。

**真实例句**（抽象）：

```
不要使用 subagent，直接执行
不需要启动项目服务，结果仅覆盖现有测试断言
```

**为什么会犯**：模型倾向于"用更重的工具显得更认真"。

**怎么避免**：
- 用户侧：明确禁止（`不要用 subagent`）
- 模型侧：用满足需求的最小工具

**对应卡**：18 边界指令

---

## 8. 顺序颠倒

**症状**：先做了 Y，但应该先做 X。

**真实例句**（抽象）：

```
顺序错误会让中文交叉审计页被英文校验页覆盖
顺序错误导致模块加载失败（OPTION_KEYS 未初始化）
需要先修交互，再补页面使用说明
```

**为什么会犯**：没识别依赖关系。

**怎么避免**：
- 动手前画出依赖顺序（谁必须先完成）
- 用卡 05 的批次推进：每批收口再开下一批

**对应卡**：05 批次推进

## 三条通用规律

### 规律 1：错误几乎都发生在"边界"上

越界（过度扩展）、不足（漏）、顺序错、形态错——都是**边界判断失误**。

### 规律 2：模型默认"做得更多"

不加约束时，模型倾向扩展、重构、加功能。
**用户侧的解法**：明确说"不要什么"（卡 18）。

### 规律 3：失败信号比成功信号更早出现

`根因不是 X` 这类句子，往往出现在**修错一次之后**。
**读法**：如果一句话里有"其实""原来""才发现"，前面通常藏着一次误判。

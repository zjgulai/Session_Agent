# ANB 维度补充（C 方向）

> ANB 覆盖了「七阶段 × 误判 × 检查」，但有五个维度它没讲。
> 按 ANB 的阶段归位，保持它的结构。
> **本版已按复核建议收敛**：去掉个人数据、去掉误导性百分比、补足案例。

## 补充 1 · 状态继承（放「管理」）

### ANB 讲了什么

管理页有「八个寄存器」「状态是目录」「证据是可复跑的命令」——**讲的是怎么记录**。

### ANB 没讲什么

**自动流程重跑时，怎么不把人工判断冲掉。**

### 补充内容

**核心不变量（provenance-aware）**：

> **只重算"自己产出的状态"；人判断的、用户未提交的、历史产出的，只继承。**

| 状态来源 | 处理 |
|---|---|
| 本流程上次产出 | ✅ 可重算 |
| 人审批/选中/标注 | ❌ 继承 |
| 用户未提交工作树 | ❌ 不碰 |
| 历史快照/旧结论 | ❌ 标记为历史，不删除 |
| 原始输入 | ✅ 可重新读取 |

**三条规则**：
1. 人工字段必须继承（重建时读取并保留）
2. 失败只追加，不清空（保留上一次成功结果）
3. 重做回到原始输入（不基于失败输出迭代）

### 三个真实案例

**案例 1 · 人工判断被脚本打回**

> `selected_outputs 这些人工审计字段必须继承，避免下一次脚本重建把已完成候选又打回 pending`

重建脚本从零开始，把人工选中的结果重算成了"待定"。

**案例 2 · 一次失败清空历史成果**

> `失败 run 只能记录错误，不能清空已有成功 top papers`

网络或配额导致某次失败，不能把之前成功的结果一起清掉。**失败只追加，不改写。**

**案例 3 · 基于失败输出重做，误差累积**

> `重做永远回到原人物照、物件照和主题母版，不让上一轮生成图继续污染身份`

生成式任务的返工，如果拿上一轮输出当输入，错误会逐轮放大。**重做必须回到原始输入。**

### 为什么 ANB 需要它

ANB 说"状态是目录"，但没说**目录里的内容是谁写的**。自动脚本重建目录时，会把人写的内容一起重算掉。

### 与"幂等"的区别

| | 幂等 | 状态继承 |
|---|---|---|
| 保证 | 重复执行收敛到同一状态 | 不重算**外部来源**的状态 |
| 盲区 | 人工判断算不算"同一状态"？ | — |

**一个完全幂等的流程，仍可能覆盖人工审批。**

## 补充 2 · 边界指令（放「需求」与「管理」）

### ANB 讲了什么

需求页讲"怎么把一个想法问成可验收的意图"；管理页讲"怎么记录"。

### ANB 没讲什么

**派活时怎么划边界，AI 才不会做偏。**

### 补充内容

**七类边界**：

| 维度 | 一句话 | 典型句式 |
|---|---|---|
| **动作禁止** | 哪些动作不许做 | `不要修改代码` · `不要启动服务` |
| **努力/深度上限** | 探索到什么程度停 | `不要继续探索，直接给结论` |
| **输出裁决格式** | 必须给什么格式 | `列出 P0/P1/P2，给 PASS 或 BLOCKED` |
| 呈现形式 | 字体/语言/版式 | `字体 10–12 号` · `只要中文` |
| 风格品牌 | 调性 | `不要渐变，要简约` |
| 主题范围 | 覆盖哪些对象 | `我要全品类` |
| 数据处理 | 真实/脱敏 | `真实金额全部写入，不要脱敏` |

**关键句**：`不要 {X}，只要 {Y}`。**"不要"比"要"更有效**——它直接封死跑偏方向。

**复合原型**（出现最多）：
```
停止当前探索 → 不要扩大范围 → 不要写文件 → 按固定格式给裁决
```

### 为什么 ANB 需要它

ANB 教"怎么验"，但验之前得先**派对活**。派活没边界，验得再好也是验一个跑偏的东西。

## 补充 3 · 上下文成本（放「开发」与「运营」）

### ANB 讲了什么

开发页讲"一条真实输入走通"；运营页讲"看得出它有没有被用"。

### ANB 没讲什么

**token 成本随会话长度超线性增长。**

### 补充内容

**实测数据**（1,176 个会话的 token 账本）：

| 指标 | 值 |
|---|---:|
| input : output | **152 : 1** |
| 每消息 token（1–9 消息会话） | 8,614 |
| 每消息 token（500+ 消息会话） | **109,818** |
| 幂律指数 | **1.43**（R²=0.748） |

**结论**：
> **成本在"读"不在"写"。长会话的成本超线性增长。**

**工程含义**：
1. **开新会话 + 断点恢复 = 降本**（500+ 消息会话总 input 是中位的 1,900 倍）
2. **优化"写得更少"节省有限；优化"读得更少"才是关键**
3. 上下文压缩要主动做（定期摘要、把探索移出主线程）

### 为什么 ANB 需要它

ANB 的"运营"讲"有没有被用"，但没讲"**用得起吗**"。一个每轮都要重发 10 万 token 的系统，规模一上来就不可持续。

### 局限

- 单一数据源（只有一种客户端的账本）
- 看不到真实费用（账本里 cost 字段为 0）
- 指数 1.43 说明有压缩机制，不是纯平方增长

## 补充 4 · 稀有真经（放各阶段的「误判」旁边）

### ANB 讲了什么

28 条误判，是**结构化的**（按阶段分布）。

### ANB 没讲什么

**低频但致命的行为**——它们不属于任何阶段，但会毁掉任何阶段。

### 补充内容（6 条）

| 真经 | 频次 | 说明 |
|---|---|---|
| **反常信号不忽略，停下来查** | 低频 | 工具输出反常时，不绕过、不重试——先确认 |
| **区分"形式通过"与"实质成立"** | 极低频 | 检查通过 ≠ 事情对 |
| **主动承认操作失误，先恢复现场** | 低频 | 错了先说，先恢复，再继续 |
| **说"只剩 X"，别说"基本完成"** | 中低频 | 精确说出还剩什么 |
| **拒绝默认做法** | 低频 | 有现成工具 ≠ 该用 |
| **纠正用户前提** | 极罕见 | 用户的前提也需要被验证 |

**最值钱的一条**：

> **反常信号不忽略，停下来查。**

实例：`nl` 读某个文件显示成二进制，但解释器刚能正常运行 → **停下确认，而不是继续编辑**。

### 为什么 ANB 需要它

ANB 的误判是"你会怎么想错"，这些真经是"**你会怎么放过一个信号**"。

## 补充 5 · 方法会变（放「元层」）

### ANB 讲了什么

一套静态方法论——"应该怎么做"。

### ANB 没讲什么

**方法落地时会变形，而变形的原因常常不是认知。**

### 补充内容

一个实测观察：

> 某段时间行为统计显示"技能使用率"断崖下降，看起来像是"方法成熟了、不再依赖工具"。
> 但追查发现：**是因为改了一次配置文件，限制了技能的自动触发**。

**教训**：

> **配置是开关，行为是水流。**
> 看到行为变化时，先排除"环境变了"，再归因于"认知变了"。

**推论**：任何"我们进步了"的结论，都要先问一句——**是不是只是换了工具/配置/流程？**

### 为什么 ANB 需要它

ANB 是一套"应该这样做"的方法。但**方法落地时会变形**，而且变形的原因常常是环境（配置、工具、团队），不是认知。

如果不区分这两者，就会把"环境变化"误读成"方法进化"，反过来指导错误的实践。

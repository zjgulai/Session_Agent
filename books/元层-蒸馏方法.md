# 元层 · 怎么把会话历史蒸馏成经验

> 这一章不是经验，是**生产经验的方法**。它比任何一张卡都更可迁移——
> 换一个数据集、换一个领域，这套方法照样能用。

---

## 0. 一句话

**经验 = 问题类 × 收敛解**，且每条都要过**证据门**与**复现门**。

数据是尾矿（会过期），方法是金。

---

## 1. 判据：什么算"经验"

| 类型 | 频率 | 价值 | 处理 |
|---|---|---|---|
| 通用套话（"写测试""小步提交"） | 极高 | 低 | **丢弃**（跨类普遍出现 = 低 lift） |
| 问题类收敛解 | 高 | **高** | **收** |
| 稀有真经（坑/反直觉） | 低 | **高** | **单列**（反例与坑清单） |

- **support 阈值**：同一类下 ≥3 记入，≥10 高置信。
- **lift 过滤**：出现在所有类里的做法 → 套话 → 丢。
- **频率必要不充分**：必须**条件在问题上**才有价值。

---

## 2. 三个关键区分（最容易混，混了就错）

### 2.1 问题类 vs 跨类技法

| | 问题类 | 跨类技法 |
|---|---|---|
| 是什么 | 你去**请求**的任务 | 你在任务里**用**的做法 |
| 判据 | **用户请求**命中模板 | **助手回应**命中行为 |
| 例 | 断点恢复、批次推进、能力图谱 | **对抗性审查（30%）**、**视觉验收（16%）** |

**判据用错会致命**：把技法当问题类，严格类只剩 9 会话，置信级假跌到"低"。
**自查**：如果某"类"的显式请求很稀有，但行为遍地都是 → 它是技法。

### 2.2 脚手架 vs 涌现

**脚手架** = 你写在配置里的（AGENTS.md / skills / agents / hooks）。
**涌现** = 模型自己在会话里收敛出来的。

**判据**：把配置语料建成一个集合，**涌现 = 高频 且 不在配置里**。

> 例：`不叠加 patch` 写在 AGENTS.md，实测仅 **1%** → 是配置回声，不是经验。
> 例：`隔离优先` 配置里没有，实测 **51%** → 是真涌现。

### 2.3 配置 ≠ 执行（反直觉）

**配置是"应该怎么做"，数据是"实际怎么做"。两者差距本身就是经验。**

| 配置要求 | 实测执行率 |
|---|---:|
| 不叠加 patch | 1% |
| 修复后清理 | 5% |
| 根因定位 | 30% |
| 验收方式 | 36% |

→ 别把"配置写了"当成"经验成立"。

---

### 2.4 数据里最跨类的一条纪律：A ≠ B

深挖已有卡时发现的**单一最跨类行为**：**证据升级拒绝**，出现在 **30%** 的全部会话里。

它说的是同一件事：**不许把低等级证据说成高等级结论**。

| 低等级 | ≠ | 高等级 |
|---|---|---|
| 已安装 | ≠ | 已认证 / 调用成功 / 生产可用 |
| 代码存在 | ≠ | 功能完成 / 已验收 |
| 测试绿 | ≠ | 风险关闭 |
| 草稿存在 | ≠ | 允许发送 |
| 文档样例 | ≠ | 真实目录 |
| 本地 E2E | ≠ | 线上巡检 |
| 环境缺口 | ≠ | 代码失败 |
| 引用 | ≠ | 已采用 |

**它是所有经验卡的共同底座**：每张卡的核心句，本质都是 A ≠ B 的一种具体形式。

> **深挖的方法论收获**：不要只找"新问题类"（样本会薄）。
> **找跨类的高频行为**——它们覆盖率高、可迁移、且是各卡的共同地基。

## 3. 类判据的设计（决定成败）
1. **用特异性高的词。**
   - ✅ `断点` `对抗性审查` `handoff` `能力图谱` → 干净
   - ❌ `错误` `bug` `失败` → **跨类高频词**，会把你想要的类灌满评审会话

2. **语义聚类合并同义措辞。**
   - 用户换说法就漏 → 严格类偏小。
   - 做法：抽全部唯一模板 → 按语义合并 → 回到全量重算。
   - 实测效果：断点恢复 79→118、交接收尾 16→62。

3. **验证类边界。** 出卡前先看样本里"真属于该类"的比例。
   - 若真类 < 30% → 判据错了，回去改。

---

## 4. 两道门（防止自欺）

### 4.1 证据门（逐卡）

每条结论必须带：
- support 计数 + **口径**（样本级 / 全量级）
- 会话级**证据指针**（源 / 日期 / 项目，**不含原文**）
- 反例与边界
- 置信级（高 / 中 / 低）

### 4.2 复现门（抽样）

**第二个模型**读同一批会话，**不知道你的结论**，独立抽取；比对一致率 ≥70% 才算过。

**它最有价值的不是"拦下假的"，而是"发现真的被判错了"**。实测战绩：
- 纠正 **5** 次（样本分类错、漏句式、误读词、高估 MECE、归类错）
- 拦下 **1** 张真假卡（核心句是脚手架）
- **救回 2 张被误判的真卡**（样本污染、归类错）

**裁决只有三种**：VERIFIED / NOT VERIFIED / INCONCLUSIVE。**INCONCLUSIVE 不算过。**

---

## 5. 沉淀格式（经验卡 B+C）

每张卡 = **场景 → 问题 → 解决方案 → SOP → 反例与坑 → 案例 → 收敛解对照**。

颗粒度 **B+C**：
- **B（逐步支撑）**：SOP 每步带独立 support + 触发 + 决策点。
- **C（指令形状）**：抽出可复制的句式，缺槽 = 缺约束。

**关键句**：每张卡要有一句"缺了它就退化"的核心句。

---

## 6. 隐私

**抽象成模式，不引用原话。** 会话可能含客户/业务信息。
证据用指针（源/ID/日期），正文只放提炼后的做法与结论。

---

## 7. 流程（可复制）

```
1. 定位数据源（Codex / opencode / Claude 会话存储）
2. 归一化：抽取用户请求 + 助手回应，剥离注入块
3. 问题类：抽唯一模板 → 语义聚类 → 全量重算
4. 分类：问题类 or 跨类技法（看判据命中在哪一侧）
5. 剔除：配置语料差集 → 只留涌现
6. 出卡：B+C 格式 + 证据门
7. 复现门：第二模型独立抽 → 一致率 ≥70%
8. 沉淀：分册 + 总索引 + support 报告
```

## 8. 已证伪的做法（别再犯）

| 做法 | 后果 |
|---|---|
| 用关键词判类 | 得到"关键词桶"，命中虚高、类不纯 |
| 把技法当问题类 | 置信级假跌，卡被误杀 |
| 把配置当经验 | 把脚手架原样还给用户，零价值 |
| 正则放宽捞样本 | 样本被污染，核心主张被否 |
| 不跑复现门 | 假卡进手册，掺沙 |
| **用"技能提及率"判脚手架** | **无区分度**：全量基线 59%，已发布卡也是 69–78% |
| **只看行为名不查技能原文** | 会漏判：`基线对比` 51% 看似涌现，实则 benchmark-checklist 明文规定 |

### 判脚手架的**正确**做法

不是"这个会话提没提技能"，而是：

1. 打开技能文件，搜索该行为的**原文规定**（中英双语）。
2. 技能明文规定了 → 脚手架。
3. 技能 0 次提及但会话高频 → 涌现。

**实测对照**：

| 行为 | 技能文本提及 | 会话覆盖 | 判定 |
|---|---:|---:|---|
| 验证 / verification | 216 | — | 脚手架 |
| 基线对比 / baseline | 11 + benchmark 技能明文 | 51% | **脚手架** |
| 自检 / self-check | **0** | **42%** | **涌现** ✅ |
| 复核 / re-review | **0** | 41% | 涌现 |
| 复盘 / retro | **0** | — | 涌现 |

> **教训**：技能是英文的，中文行为词在技能文本里天然为 0。
> 必须**双语搜**，否则会把自己的英文技能当成"未规定"。

---

## 9. 这套方法的迁移性

它不依赖"Codex 插件"或"coding 会话"。

**任何"有大量历史记录、想提炼可复用经验"的场景都适用**：
客服对话 → 服务话术；销售记录 → 成交方法；会议纪要 → 决策模式；工单 → 故障处置。

**核心不变**：收敛解 + 脚手架剔除 + 复现门。

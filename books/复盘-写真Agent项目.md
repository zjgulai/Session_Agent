# 项目复盘 · AI 写真生成 Agent

> 6 天（2026-10-15 → 10-25），230 个会话，147 万字符的助手输出。
> 从"借鉴一个开源方法"到"一套可验收的内容生产系统"。
> 本复盘抽象化处理，不含业务品牌与人物信息。

---

## 一、项目目标

不是"生成好看的图"，而是：

> **把"同一个人、必须好看、风格明显不同"拆成可控制、可比较、可验收的生产系统。**

这句话是整个项目的北极星。它把主观的"好看"变成了工程问题。

---

## 二、6 天生命周期

| 日期 | 会话 | 阶段 | 在做什么 |
|---|---:|---|---|
| 10-15 | 29 | **借鉴** | 找开源方法论、采集素材、按场景分类 |
| 10-18 | 72 | **生产** | UI 完善、主题挖掘、案例保存、目录重构 |
| 10-19 | 83 | **工程化**（峰值） | 状态机、合同、门禁、批次运行 |
| 10-20 | 24 | **审计** | 只读审查、无障碍验证、合同审计 |

**关键转折**：10-19 之后，会话性质从"生成内容"变成"审计合同"。项目从**探索期进入工程期**。

## 三、核心方法论（5 条）

### 1. 重做必须回到原始素材（最重要）

> **重做永远回到原人物照、物件照和主题母版。**
> **不让 AI 图递归污染脸。**

**为什么关键**：生成式任务的返工，如果基于上一轮输出迭代，误差会累积——脸会越来越不像本人。

**可迁移**：任何迭代式生成（文本改写、数据清洗、模型训练）都适用。
**规则**：失败输出只用于**诊断**，不进入下一轮输入。

### 2. 把主观质量拆成可打分的维度

质检维度按出现频次：

| 维度 | 频次 |
|---|---:|
| **身份一致性** | **1,298** |
| 构图 | 398 |
| 比例 | 315 |
| 连续性 | 310 |
| 服装 | 304 |
| 表情 | 287 |
| 眼神 / 姿态 / 手势 | 159 / 101 / 76 |

**身份一致性是绝对核心**（比其他维度高 3 倍以上）。

**评分门槛**（真实规则）：
- 普通入选：总分 ≥ 85
- 主视觉：总分 ≥ 92
- 身份不得低于 25/30
- 美感不得低于 21/25

### 3. 三阶段门禁（Gate 1 → 2 → 3）

| Gate | 出现次数 | 作用 |
|---|---:|---|
| Gate 1 | 274 | 基础筛选 |
| Gate 2 | 215 | 质量提升 |
| Gate 3 | 245 | 交付验收 |

**每个 Gate 都不可绕过**，且"不能绕过人工审核门槛"。

### 4. 领域模型代替散落逻辑

| 模型 | 频次 | 作用 |
|---|---:|---|
| AlbumPlan | 188 | 专辑计划 |
| SelectionSet | 138 | 选片集合 |
| RepairPlan | 107 | 修复计划（可修改项 + 锁定项） |
| ReferenceSet | 107 | 参考集合 |
| CaseWorkspace | 29 | 案例工作区 |

**RepairPlan 的关键设计**：明确列出"可修改项"与"锁定项"，且**被编辑的成片不能自动升级为身份参考**。

### 5. 测试隔离：Fake Provider

- 用 Fake Provider 做测试替身（140 次提及）
- **Live test 必须由开发者显式开启，不进入普通 CI**
- 避免真实 Provider 重复计费

## 四、踩过的坑

| 坑 | 表现 | 解法 |
|---|---|---|
| **代际污染** | 失败图递归修脸，越修越不像 | 回到原始素材重做 |
| **身份漂移** | 多轮生成后脸变了 | 身份维度单独评分，<25/30 直接拒 |
| **自动近景倾向** | 模型总把人物拉近 | 加"相机距离 7–10 米 + 占画布高度上限"双重约束 |
| **细节失控** | 猫耳、多余手指、比例失调 | 每轮验收列具体检查项 |
| **重复计费** | 真实 Provider 重跑 | Fake Provider + Live test 显式开启 |
| **绕过门禁** | 想跳过人工审核 | 门禁硬编码，不可绕过 |

---

## 五、可迁移的结论

### 结论 1：生成式项目的核心是"控制代际污染"

不管生成的是图、文、还是数据，**返工必须回到原始输入**。否则每一轮都在放大上一轮的错误。

### 结论 2：主观质量必须拆成可打分的维度

"好看"无法验收，"身份 25/30、美感 21/25、构图 30/30"可以验收。

### 结论 3：门禁要硬，不能"这次特殊"

三阶段 Gate 都不可绕过。一旦允许例外，门禁就失效了（对应卡 17 默认拒绝）。

### 结论 4：测试替身是成本控制的关键

Fake Provider 让开发不用真实调用，Live test 只在显式开启时跑。

### 结论 5：项目会在某个点从"生产"转向"审计"

10-19 之后，大部分会话变成只读审查。**这是项目成熟的信号**——从"做出来"到"证明它是对的"。

## 六、这个项目验证了手册里的哪些卡

| 卡 | 在本项目中的体现 |
|---|---|
| 01 只读审计 | 10-20 之后大量只读审查会话 |
| 02 项目诊断 | 多次"深度审计 + 债务清单" |
| 05 批次推进 | 14 主题 × 4 镜头的分批运行 |
| 12 证据升级拒绝 | "被编辑的成片不能自动升级为身份参考" |
| 15 完成前自检 | 每轮验收的具体检查项 |
| 17 默认拒绝 | Gate 不可绕过、Live test 默认关闭 |

**手册里的纪律不是抽象的——它们在这个项目里都是具体规则。**

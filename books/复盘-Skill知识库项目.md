## 一、项目目标

把学术论文与外部方法论，加工成**可执行的技能单元**，再组织成知识图谱，用于产出选题与 playbook。

**流水线**：论文（arXiv）→ Skill → 知识图谱 → 缺口分析 → 选题 → Playbook

## 三、核心方法论（4 条）

### 1. 单一快照，不手工维护统计

> **计划里不能只"修文档"，要建立从文件系统自动重建统计的单一快照。**

**为什么**：手工维护的数字一定会漂移。文档说 42 个 Skill，实际 47 个——这种不一致会累积。

**做法**：统计从文件系统自动重建，文档只是快照的呈现。

### 2. 不能为了测试而伪造数据

> **不能为了测试硬造"缺桥"。**
> **为满足"新增领域必须参与 gap/选题链路"的治理目的，我会加入低优先级 review 项，而不是伪造断链。**

**为什么**：伪造数据能让测试通过，但破坏了图谱的真实性。

**做法**：宁可加一个真实的低优先级项，也不造一个假的。

### 3. 失败不能清空成功结果

> **失败 run 只能记录错误，不能清空已有成功 top papers。**

**为什么**：一次失败的采集不应该让之前的成果消失。

**做法**：失败只追加错误记录，保留上一次成功结果。

### 4. 人工状态必须继承

> **`selected_outputs` 这些人工审计字段必须继承，避免下一次脚本重建把已完成候选又打回 pending。**

**为什么**：自动流程重新生成时，会把人工确认过的状态覆盖掉。

**做法**：重建脚本必须读取并保留人工字段，不能从零开始。

## 四、与写真项目的共性

两个项目看似不同（一个生成图像，一个加工知识），但暴露了**同一类问题**：

| 问题 | 写真项目 | 知识库项目 |
|---|---|---|
| **人工成果被自动流程覆盖** | 被编辑的成片不能自动升级为身份参考 | 人工审计字段必须继承 |
| **失败/错误递归污染** | 重做回到原始素材，不让 AI 图递归污染 | 失败 run 不清空成功结果 |
| **数据真实性** | 不伪造 SHA、不绕过人工审核 | 不为测试硬造缺桥 |
| **统计漂移** | 主题目录要可重建 | 统计从文件系统自动重建 |

### 统一成一条原则

> **自动流程可以重跑，但不能覆盖人工判断，也不能让失败污染成功。**

这条原则可以泛化到任何"人机协作的生产系统"：
- 内容生成（图/文/视频）
- 数据流水线
- 知识库维护
- 模型训练

## 五、踩过的坑

| 坑 | 表现 | 解法 |
|---|---|---|
| **文档与实现漂移** | 文档说 42，实际 47 | 从文件系统重建统计 |
| **测试驱动造数** | 为让测试过而伪造缺桥 | 加真实低优先级项 |
| **失败覆盖成功** | 一次失败清空历史结果 | 失败只追加错误 |
| **重建覆盖人工** | 脚本把 selected 打回 pending | 继承人工字段 |
| **脏工作区被覆盖** | 自动流程改动用户未提交内容 | 明确"保护现有脏工作区" |

## 六、可迁移的结论

### 结论 1：人机协作系统最大的风险是"覆盖"

自动流程天然倾向于"重新生成"，但人工判断的价值恰恰在"不该重算的部分"。

### 结论 2：失败处理比成功处理更重要

成功路径容易写对，失败路径容易写坏——尤其"失败时是否破坏已有状态"。

### 结论 3：统计必须可重建

任何手工维护的数字都会漂移。让数字从源头自动算出来。

### 结论 4：长任务要分期

`Sprint` / `Phase` 高频，说明复杂任务必须切成有检查点的阶段（对应卡 05）。

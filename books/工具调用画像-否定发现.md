# 工具调用画像（含两次否定发现）

> 尝试从 Codex rollout 的工具调用序列里蒸馏经验。
> **结论：两个假设都被证伪。但画像本身有信息。**

---

## 一、数据与口径

- 来源：`~/.codex/sessions/**/rollout-*.jsonl.zst` 的 `response_item.custom_tool_call`
- 抽取：120–300 个 rollout 随机样本
- 分类：按 `tools.<fn>(` 与 `cmd` 解析

## 二、工具调用画像（描述，非经验）

| 类别 | 占比 | 说明 |
|---|---:|---|
| `exec_script` | **37%** | 内联脚本（node/python/sh） |
| `agent:*` | **28%** | wait_agent 16% + send_message 5% + 其他 |
| `read` | 10% | cat/sed/head/nl |
| `edit` | 8% | apply_patch |
| `search` | 6% | rg/grep/find |
| `git` | 3% | status/diff/log |
| `test` | 2% | pytest/npm test |
| `build` | 0.4% | tsc/build/lint |

**每次 rollout**：中位 21 次调用，平均 70，最大 2,820。

### 画像能说明什么

1. **大部分工作是"跑脚本验证"（37%），不是"读改代码"**。
2. **agent 类占 28%**——但这是**预配置的子代理脚手架**，不是涌现（见卡 09 的教训）。
3. **test/build 只占 2.4%**——测试不是主要动作，验证更多靠临时脚本。

## 三、否定发现 1：读改比与返工无关

**假设**：动手前读得多、搜得多，返工率低。

**初次观测**（按调用占比）看起来支持：

| 工具占比 | 有修正 | 无修正 |
|---|---:|---:|
| read | 7% | 10% |
| search | 5% | 7% |
| edit | **9%** | **5%** |

**按会话级重算**（读改比 = (read+search)/edit）：

| 组 | n | 中位 | 均值 | 读改比 >2 的比例 |
|---|---:|---:|---:|---:|
| 有修正 | 13 | **0.0** | 0.7 | 15% |
| 无修正 | 22 | **0.1** | 0.9 | 14% |

**结论：无显著差异。**

**为什么第一次看起来有差异**：辛普森悖论——长会话 `exec` 调用多，稀释了 read/search/edit 的**占比**。按占比比较，长短会话不可比。

---

## 四、否定发现 2：修正成本的倍数差异是极值假象

**假设**：需要用户修正的会话，成本显著更高。

**均值**：
- 有修正：215.7 次调用
- 无修正：37.0 次调用
- **倍数 5.8x** ← 看起来很强

**中位数**：
- 有修正：21
- 无修正：23
- **倍数 0.9x** ← 几乎无差异

**结论：差异完全来自少数超长会话，中位会话没有区别。**

---

## 五、为什么工具调用层难出经验

| 原因 | 说明 |
|---|---|
| **无成败标记** | 语料里没有"任务成功/失败"的确定标签，只能用用户修正做代理 |
| **规模主导** | 调用次数主要由任务大小决定，不是方法好坏 |
| **长尾极值** | 少数 500+ 调用的会话能翻转均值 |
| **脚手架混淆** | agent 类占 28%，是预配置不是涌现 |
| **代理指标弱** | "用户修正"不等于"任务失败"，也可能只是需求变了 |

---

## 六、这本身是一条经验

> **不是所有维度都值得蒸馏。**
> 工具调用序列看起来"有数据、可量化"，但缺少成败标签和规模归一化时，任何差异都可能是指标假象。

**对应方法**：
- 先做**会话级**比较，再做**占比**比较（防辛普森悖论）
- 同时看**均值和中位数**（防极值主导）
- 没有成败标签时，不要用"用户修正"当唯一代理

**对应卡**：12 证据升级拒绝（`占比差异 ≠ 会话级差异`）、14 证据锚定（给出口径）

---

## 七、若要继续挖，需要什么

1. **明确的成败标签**（任务是否完成、是否返工）
2. **按任务规模归一化**（同类任务内部比较，而不是跨任务）
3. **区分脚手架与涌现**（agent 类单独统计）
4. **更大的样本**（当前 100–300 个 rollout，长尾影响仍大）

### 02 · 项目诊断→债务→方案（本册核心）

**收敛解**：**五段协议**——元声明 → 现状画像 → 分层排查与验证 → 严重度排序清单 → 分阶段方案。

**SOP**
1. **开场元声明方法**（点名方法与工具）。
2. 建立现状画像：结构、入口、配置、依赖、测试。
3. 分层排查 + **经验性验证**（跑脚本/测试/构建）。
4. **发现锚定到文件/行，并标证据级**。
5. 产出问题清单，按严重度排序（P0/P1/P2）。
6. 分阶段方案。
7. 测试矩阵 + 验收标准（**注：最弱段，纯类里仅 ~3/7 真做到，别当默认产出**）。
8. 声明非破坏性边界。
9. 结尾给下一步 / 门 / 交接。

**债务分类（固定词表）**：脆弱点 / 风险点 / 技术债务 / 工程债务 / 项目管理债务 / 文档管理债务。

**指令形状**
```
我会先 {侦察}，再 {逐层检查}，把 {发现} 按 {严重度} 排序，
然后产出 {分阶段方案} + {测试矩阵} + {验收标准}；
本轮只做 {非破坏性探索}，{不会改文件 / 不会提交}。
```

## 本册的方法论要点

- **诊断的产物必须可执行**：问题清单不带严重度 = 没给。
- **"测试矩阵 + 验收"是弱段**：多数会话只是"声明了要做"，不是真做了。别把它当默认产出。
- **先画像再下结论**：不建画像直接列风险，清单是猜的。

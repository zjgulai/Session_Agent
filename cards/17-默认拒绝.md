# 经验卡 · 默认拒绝（跨类纪律）

> **本卡是跨类纪律。** 数据里第五条高覆盖行为：**21%** 的会话采用"默认拒绝，明确通过才放行"。

- **类型**：跨类纪律
- **身份**：Agent 全栈 / 产品经理
- **support**：出现在 **592/2,787 = 21%** 会话中。对照：**"默认允许"仅 1%（41）**——说明这是有意识的选择，不是默认行为
- **置信级**：**中**（21% 覆盖 + 技能零提及；覆盖率低于卡 12–16，但结构极清晰）
- **脚手架判定**：**涌现**。技能文本 `fail-closed` **0 次**、`allowlist` 2 次、`deny` 5 次（均为零散提及，无纪律规定）
- **口径**：全量

## 场景

设计一个**放行/阻断**的判断：发布什么、导出什么、允许什么、覆盖什么、渲染什么。

## 问题

- 默认允许 → 漏掉的就放出去了（黑名单永远列不全）。
- 只拦已知危险项 → 新危险项直接通过。
- 出错时放行 → 失败即泄露。

## 解决方案（收敛解）

**默认拒绝，只有明确满足条件才放行；任何命中阻断项即阻断。**

核心：**白名单而非黑名单；失败时关闭而非打开。**

## SOP（每步带独立 support）

| 步 | 动作 | support | 触发 | 决策点 |
|---|---|---:|---|---|
| D1 | **默认状态设为"拒绝"** | **13/20** | 设计放行逻辑时 | 默认允许 → 漏项直接通过 |
| D2 | **用白名单**（枚举允许项，其余排除） | **13/20 明确 · ~17/20 隐含** | 总是 | 黑名单 → 列不全（**注：可黑白名单并用，见下**） |
| D3 | **在源头不产出，不靠拦截** | 3/20 | 有发布/导出 | 先发后藏 → 拦截漏了即泄露 |
| D4 | **明确放行条件：全部满足才过** | 11/20 | 总是 | 条件模糊 → 等于默认允许 |
| D5 | **任一失败即整体阻断**（fail-closed） | 显式 3/20 · 行为 ~10/20 | 总是 | 出错时放行 → 失败即泄露 |
| D6 | **破坏性动作放最后**，且仅对已核对项、可恢复 | 3/20 | 有删除/覆盖 | 先删后验 → 不可逆 |
| D7 | **门要能失败**（先证明它会红，再信任它绿） | 3/20 | 有验证门 | 门是空转 → 假安全 |
| D8 | **拒绝时说明原因** | 总是 | 被拒时 | 静默 → 无法排查 |
| D9 | **边界路径也要拒绝**（空值/异常/未知） | 总是 | 总是 | 未知当允许 → 后门 |

## 指令形状

```
默认拒绝：只有 {全部条件} 满足才放行；任何 {阻断项} 命中即阻断。
```

典型实例（来自真实会话，已抽象）：
- `采用"默认拒绝发布"的 CI：只有脱敏、来源、内容契约、链接、移动端、可访问性和 secret scan 全部通过，main 才自动发布；任何真实 KPI、服务器地址或原始取证数据命中都会阻断。`
- `加一个默认拒绝的 public allowlist exporter 和安全测试，确保没有 allowlist 之前不能把私有材料导出。`
- `建议只发布白名单目录或 dist/，不要把内部计划、历史数据一起公开。`
- `如果路径被真实目录占用会拒绝覆盖。`
- `应加 DOMPurify/严格 CSP，并禁用原始 HTML 或只允许白名单标签。`

**关键句**：`默认拒绝：只有 {条件} 满足才放行`。缺了它，放行逻辑就是黑名单，永远漏。

> **修正（复现门）**：白名单 vs 黑名单**不是绝对二选一**。
> 有会话同时用两者：金额/KPI 用 allowlist，密钥/私有路径用 deny-list。
> 正确的表述是：**默认拒绝是根，白名单是主手段，黑名单是补充**（对已知高危项）。

## 条件变体

| 场景 | 默认拒绝的形态 |
|---|---|
| 发布 / 部署 | 全部检查通过才发布；任一命中即阻断 |
| 数据导出 | 无 allowlist 不允许导出私有材料 |
| 文件覆盖 | 目标被占用 → 拒绝覆盖 |
| HTML 渲染 | 只允许白名单标签，禁用原始 HTML |
| 权限 / 授权 | 默认只读；写操作逐次确认 |
| 测试失败 | 保留上一次成功结果，不用失败结果覆盖 |

## 反例与坑

- **默认允许 + 黑名单** → 永远列不全，新威胁直接通过。
- **出错时放行**（fail-open）→ 失败即泄露。
- **条件写"或"而非"且"** → 一个条件满足就放，等于没拦。
- **边界值当允许**（空/未知/null）→ 后门。
- **拒绝但不说明** → 无法排查，用户不知道为什么被拦。
- **边界**：纯读、无放行决策的场景不适用。

## 案例（抽象）

- 发布 CI：默认拒绝，七项检查全绿才自动发布，任一敏感命中即阻断。
- 数据导出：无 allowlist 不允许导出。
- 文件操作：路径被真实目录占用 → 拒绝覆盖，不静默替换。
- 渲染：禁用原始 HTML，只允许白名单标签 + CSP。
- 批量采集：只有上一批完成并校验，才创建下一批（顺序门）。

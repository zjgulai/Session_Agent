- **身份**：商业分析 / 产品经理

- **置信级**：中（合并类 51；核心主张 80–88% 成立；见 `../05-support-全量.md`）
- **脚手架判定**：核心行为（产物是结构化资产、区分事实与候选设计）**不在配置里** → 涌现
- **口径**：全量合并类

## 场景

看到一批有价值的外部内容（爆款、帖子、竞品原型），要把它变成**能反复用的东西**，而不是看完就忘的报告。

## 问题

- 直接抄 → 不可复用，换个场景就废。
- 只写总结报告 → 读完就忘，无法驱动后续动作。
- 把"我推断的设计"当成"来源里的事实" → 污染资产。

## 解决方案（收敛解）

**产物是结构化资产，不是报告。** 先只读盘点来源 → 拆交付层次 → **区分事实与候选** → 可追溯校验 → 落成目录/模板/字段 → 分类去重。

核心两条：**产物是资产不是报告**（88%）；**严格区分来源事实与候选设计**（80%）。

## SOP（每步带独立 support）

| 步 | 动作 | support | 触发 | 决策点 |
|---|---|---:|---|---|
| E1 | **只读盘点来源**，不写文件 | 84% | 总是 | 需落地 → 另开写会话 |
| E2 | 拆成可交付层次（解剖 + 萃取） | 45% | 内容成体系时 | 层次不清 → 先分事实层/候选层 |
| E3 | **严格区分"来源事实"与"候选设计"**，不混为一谈 | **80%** | 总是 | 混写 → 资产被污染 |
| E4 | **可追溯校验**：逐项回到原文 / 原始 JSON / 运行记录 | 82% | 总是 | 无法回查 → 标"未知"，不臆造 |
| E5 | **落成结构化资产**：目录 + 模板 + 字段 + 清单 | **88%** | 总是 | 无字段定义 → 不可复用 |
| E6 | 分类与去重 | 43% | 来源成批时 | 分类重叠 → 重分 |
| E7 | 只读边界（不调用生产服务、不改原文件） | 82% | 总是 | 涉私有素材 → 严格只读 |

## 指令形状

```
我想要将 {来源} 的核心进行提取，然后总结为 {结构化产物}。
```

模型侧展开（来自真实会话，已抽象）：

```
我会先只读盘点 {来源}，不写文件。
把这项工作拆成 {N} 个可交付层次：先 {解剖/萃取}，再基于证据提出 {候选}。
我会把 {来源事实} 与 {候选设计} 分开，不混为一谈；
逐项回到 {原文/原始 JSON/运行记录} 校验，确保可追溯。
最后落成 {目录 + 模板 + 字段 + 清单}，并分类去重。
```

**关键句**：`不把 {A} 和 {B} 混为一谈`。缺了它，资产会混入臆造。

## 条件变体

| 条件 | 变体 | 差别 |
|---|---|---|
| 来源是单篇内容 | **提炼型** | 直接抽取核心 → 落成一条资产 |
| 来源是一批内容 | **体系型** | 先分类，再逐类抽取，最后编排 |
| 来源含原型/页面 | **复刻型** | 先只读打开原型，再抽结构与交互 |
| 来源含竞品/品牌 | **对标型** | 先盘点"可见痕迹"与"可用资产"，再提替换方案 |
| 有既有骨架 | **复用型** | 挂到现有目录，不重造 |

## 反例与坑

- 写成报告 → 读完就忘，不驱动动作。
- 把推断当事实 → 后续任务基于臆造内容工作（这是最大坑）。
- 无字段定义 → 换个场景就废。
- 不做可追溯校验 → 数字与表述无法核实。
- **边界**：一次性、不会复用的内容，不值得做资产化。

## 案例（抽象）

- 从一批帖子提取制作方法 → 落成主题目录 + 提示词模板 + 字段定义。
- 从洞察报告转成可交互产物 → 结构化字段 + 模板，逐项回到原始 JSON 校验。
- 品牌资产替换：先把"当前原型中可见的品牌痕迹"与"可用 Logo 资产"分开盘点，再出 MECE 替换方案。

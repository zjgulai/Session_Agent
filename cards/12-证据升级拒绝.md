## 场景

任何**结论输出**的场合。尤其是评估、审计、诊断、验收——此时最容易把低等级证据说成高等级结论。

## 问题

- "装好了"被说成"能用了"。
- "代码写了"被说成"功能完成了"。
- "测试绿了"被说成"风险关闭了"。
- "文档这么写"被说成"事实如此"。
- "草稿存在"被说成"可以发送了"。

**每一次升级，都是一次未被证明的断言。**

## 解决方案（收敛解）

**凡结论，先问：这是哪一级证据？它够不够支撑我这句话？**

核心是 **"A ≠ B"**：把常被混淆的证据对，逐对钉死。

## A ≠ B 对照表（来自真实会话）

| 低等级 | ≠ | 高等级 |
|---|---|---|
| 已安装 | ≠ | 已认证 / 调用成功 / 生产可用 |
| 代码存在 | ≠ | 功能完成 / 已验收 |
| 页面存在 / 图谱有节点 | ≠ | 事实 / 可用 |
| 文档样例 | ≠ | 真实目录 |
| 搜索证据 | ≠ | 选题决策 |
| 草稿存在 | ≠ | 允许发送 |
| 引用 | ≠ | 已采用 / 已运行 |
| 本地 E2E | ≠ | 线上逐页巡检 |
| 环境缺口 | ≠ | 代码失败 |
| 测试通过 | ≠ | 风险关闭 |
| 契约绿 | ≠ | 全绿 |
| 源码草稿 | ≠ | 生产源码 |
| README 声称 | ≠ | 实际实现 |

## 指令形状

```
{A} 不等于 {B}。
```

典型实例（抽象）：
- `文档样例不等于真实模型目录`
- `搜索证据不等于选题决策`
- `草稿存在不等于允许发送`
- `本地 E2E 不等于线上逐页视觉巡检`
- `环境缺口不等于代码失败`
- `不能把 "代码存在" 升级为 "功能完成"`

**关键句**：`{A} 不等于 {B}`。**输出结论前，先说出这句话。**

## 用法（三步）

1. **识别**：我要说的这句话，属于哪一级证据？
2. **对照**：查上面的 A ≠ B 表，看是否在升级。
3. **降级表述**：说成证据实际支持的等级；不够就标"待验证"。

## 反例与坑

- **最常见的坑**：把"工具跑通了"说成"功能可用"。
- 把"测试通过"说成"没问题"（测试通过 ≠ 风险关闭）。
- 把"文档这么写"当事实（README 声称 ≠ 实际实现）。
- 把"环境报错"当代码缺陷（环境缺口 ≠ 代码失败）。
- **边界**：无。**这是全类通用纪律**，没有"不适用"的场景。

## 案例（抽象）

- 能力图谱：`禁止继续混用"代码存在""功能完成""已验收"`。
- 批次推进：`不能宣称 insight contract 全绿`。
- 内容提取：`不能称作 Qoder 的全页面、全交互完整复刻`。
- 交接收尾：`避免把"引用"误写成"已采用或已运行"`。
- 视觉验收：`这是本机网络层限制，不是站点已经返回错误`。

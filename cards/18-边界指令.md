# 经验卡 · 边界指令

- **身份**：跨三岗（给 AI 派活时用）
- **问题类**：怎么下指令，AI 才不做偏、不做多、不做少
- **support**：含明确边界指令的会话 **321/2,787 = 12%**
- **维度分布（复现门，20 会话样本）**：
  - **动作禁止 12/20**
  - **努力/深度上限 9/20**
  - **输出裁决格式 7/20**
  - 呈现形式 4 · 风格品牌 4 · 主题范围 3 · 数据处理 2 · 速度 1
- **置信级**：中（12% 覆盖；且维度是**重叠**的，不是互斥分区）
- **脚手架判定**：**涌现**。用户自己在会话里写的指令，不在任何配置里
- **口径**：全量（用户侧）

## 场景

给 AI 派活。它做完了，但做偏了、做多了、做少了，或者该停没停。

## 问题

- 只说"做什么"，没说"不做什么" → 顺手做了别的。
- 只说"分析一下"，没说何时停 → 探索 50 轮还没结论。
- 只说"改"，没说只改哪里 → 重构整个文件。
- 只说"做个页面" → 给了完整工程，你要的是单页。
- 只说"高级一点" → 给了渐变，你要的是简约。

## 解决方案（收敛解）

**边界不只一种。至少七个方向，缺哪个，AI 就在哪个方向跑偏。**

> **重要修正（复现门）**：这不是互斥的六维分区，而是**重叠的七类约束**。
> 一个会话常同时命中 3 类。最常见的复合原型是：
> **停止探索 + 不要扩大 + 固定裁决格式**（review 类会话反复出现）。

## 七类边界（按样本频率）

| # | 维度 | 一句话 | support | 典型句式 |
|---|---|---|---:|---|
| 1 | **动作禁止** | 哪些动作不许做 | **12/20** | `不要修改代码` · `不要写文件、不要运行测试` |
| 2 | **努力/深度上限** | 探索到什么程度停 | **9/20** | `不要再运行长测试` · `不再扩大扫描` · `别钻小细节` |
| 3 | **输出裁决格式** | 必须给什么格式的结论 | **7/20** | `列出 P0/P1/P2，给 FINAL PASS 或 BLOCKED` |
| 4 | 呈现形式 | 字体/语言/版式 | 4/20 | `字体调小，10–12 号` · `只要中文` |
| 5 | 风格品牌 | 调性、配色 | 4/20 | `不要深色风格` · `不要渐变，要简约` |
| 6 | 主题范围 | 覆盖哪些对象 | 3/20 | `我要全品类，不要只限制这一点` |
| 7 | 数据处理 | 真实/脱敏/来源 | 2/20 | `真实金额全部写入，不要脱敏` |
| — | 速度 | 快一点 | 1/20 | `我必须要你快一些`（太薄，并入 #2） |

**读法**：前三个是主力（动作、深度、格式），后四个是场景补充。

## SOP

1. **动作禁止**：列"不要做什么"（改文件/跑测试/连数据库/部署）。
2. **努力上限**：写"到什么程度停"（不要继续探索 / 不要跑全量 / 直接给结论）。
3. **输出格式**：写"结论长什么样"（PASS/FAIL、P0/P1/P2、file:line）。
4. 视场景加：**呈现形式 / 风格 / 主题范围 / 数据处理**。
5. **把边界独立成句，放末尾或开头**——埋在长文中间会被忽略。

## 指令形状

```
{做什么}。
不要 {禁止的动作}。
不要继续 {探索/扩大/跑全量}；{到 X 就停，直接给结论}。
结论必须包含：{格式要求，如 P0/P1/P2 + file:line}。
{风格/数据/范围}：要 {X}，不要 {Y}。
```

## 真实例句（抽象化）

| 维度 | 原话（抽象） |
|---|---|
| 动作 | `先跟我讨论方案，不要修改代码` |
| 动作 | `不要使用 subagent，直接执行` |
| 深度 | `请停止任何仍在运行的验证进程，立即基于已完成审查返回最终结论` |
| 深度 | `不要再运行长测试，主任务已完成全量验证` |
| 格式 | `列出已确认的 P0/P1/P2，并立即给 FINAL COMMIT READY 或 BLOCKED` |
| 范围 | `其他品类我也是需要的，你不能只限制这一点点范围` |
| 呈现 | `ppt 的字体字号要普遍调小，10–12 号就好` |
| 风格 | `不要渐变风格，要简约高端大气，文字有层级关系` |
| 数据 | `真实金额和 KPI 全部写入，不要脱敏` |

**关键句**：`不要 {X}，只要 {Y}`。**"不要"比"要"更有效**——它直接封死跑偏方向。

## 复合原型：review 收敛

最高频的组合（sessions 11–19 反复出现）：

```
停止当前探索 → 不要扩大范围 → 不要写文件 → 按固定格式给裁决
```

**为什么有效**：同时封住了三个最常见的失控方向——继续探索、顺手改动、结论含糊。

## 助手遵守率

**19/20 遵守**。唯一"违反"的一例（用户要真实金额不脱敏，助手援引安全规则拒绝）其实是**正确行为**——说明边界指令与安全规则冲突时，安全规则优先。

## 反例与坑

- **只说"要什么"不说"不要什么"** → AI 会顺手加东西。
- **说"分析一下"不说何时停** → 无限探索。
- **说"高级一点"不给方向** → 猜错风格。
- **边界埋在长文中间** → 被忽略。
- **边界与安全规则冲突** → 安全规则优先，不会照做。
- **边界**：探索性任务（还不知道要什么）不适合过早划死边界。

## 复现门（P2）

- **方法**：第二个模型（Sonnet）读 20 会话样本（`_raw/sample-boundary.md`），独立抽取。
- **结果**：**通过，但推翻了初版框架。**
- **证实**：动作禁止是最频繁维度（12/20）；助手遵守率 19/20。
- **修正 ①（重要）**：初版的"六维互斥框架"**不成立**。独立模型原话："a loose, overlapping taxonomy, not a clean six-way partition." 一个会话常同时命中 3 类。
- **修正 ②**：初版把"停止探索/不要扩大"归进"范围边界"是**错的**。它是独立的**努力/深度上限**（9/20），且和"主题范围"（3/20）是两回事。
- **增量 ③**：初版**漏了"输出裁决格式"**（7/20）——`必须给 PASS/FAIL、P0/P1/P2、file:line`。这是 review 类会话最稳定的约束。
- **增量 ④**：识别出复合原型「停止探索 + 不扩大 + 固定格式」，比单维更实用。
- **裁决**：PASS（带三处修正）。置信级 中。

# 经验卡 · 未知标注（跨类纪律）

> **本卡是跨类纪律。** 数据里第四条高覆盖行为：**37%** 的会话把"不知道"明确标出来，而不是猜。

- **类型**：跨类纪律
- **身份**：跨三岗
- **support**：出现在 **1,038/2,787 = 37%** 会话中。结构：边界 93% · 证据 84% · **未知 72%** · 暂不 28% · 假设 28% · 推断 24% · 标注 19% · 待验证 10% · 待确认 10%
- **置信级**：**高**（37% 覆盖 + 技能文本零纪律规定）
- **脚手架判定**：**涌现**。技能文本里 `unknown/uncertain` 出现 14 次，但**全是技术术语**（TypeScript `unknown` 类型、passive voice 的 actor unknown、riskiest-unknown-first），**没有一条是"标注不确定性"的纪律**。
- **口径**：全量

## 场景

结论需要基于事实，但有些事实拿不到：没权限、没文档、数据对不上、来源不可信。

## 问题

- 猜一个填上 → 污染结论。
- 空着不说 → 用户以为已核实。
- 笼统说"有风险" → 无法行动。
- 把模板/推测写成事实 → 下游基于假数据决策。

## 解决方案（收敛解）

**不知道就标不知道，且标得具体、标出归属。**

核心：**"未知"是一等公民，不是要藏起来的缺陷。**

## SOP（每步带独立 support）

| 步 | 动作 | support | 触发 | 决策点 |
|---|---|---:|---|---|
| U0 | **先建立已验证基线**：说清哪些核过了 | 9/20 | 总是 | 无基线 → 不知未知在哪 |
| U1 | **识别不可核实项** | 未知 72% | 总是 | 无法核实 → 不进入结论 |
| U2 | **具体标注**：不是"有风险"，是"平台 URL 待确认" | **11/20** | 总是 | 笼统 → 无法行动 |
| U3 | **标注分级**：待验证 / 待确认 / 无法核实 / 未提供 | 严格标记 7/20 | 总是 | 混用 → 不知道差在哪 |
| **U4** | **把未知移出产物**（不只是脚注）——**承重步** | **9/20** | 总是 | 只标注不剔除 → 污染仍在 |
| U5 | **仍交付可验证部分**，不因有未知就全停 | **18/20** | 总是 | 一刀切停 → 交付不了 |
| U6 | **给出补全路径**：谁去补、补什么、何时补 | 暂不 28% | 有未知时 | 不给出路 → 卡死 |
| U7 | **不把模板/推测伪装成事实** | 8/20 | 总是 | 伪装 → 信任崩塌 |

> **关键区分（复现门）**：**标注（11/20）≠ 移出（9/20）**。
> 承重槽是 **U4**：未知必须从产物里**剔除**，不只是加个脚注。标注了但还是混进去，等于没标。

## 指令形状

```
已核实：{verified_facts}。但 {unknown_item} 无法核实/待确认。
因此我会 {remove_or_defer_action}，不会 {anti_pattern}。
{同时仍交付 verifiable_deliverable}。
```

**五段核心**：`核实到的事实 → 标出未知 → 把未知移出交付物 → 否定猜测 → 继续交付可验证部分`

典型实例（来自真实会话，已抽象）：
- `现有 compare 里 BAI 的 DeepSeek-V4-Flash 条目无法核实。为了不把榜单建立在不可核实的数据上…`
- `拿不到权限的地方会明确标成待验证`
- `平台 URL 待确认`
- `AI 应用暂不混进"模型列表"，避免把模板任务伪装成模型`
- `这一轮只做只读盘点，不写文件`

**关键句**：`{X} 无法核实，标为 {待验证}`。**未知必须有名有姓，不能笼统。**

## 条件变体

| 条件 | 变体 | 差别 |
|---|---|---|
| 无权限 | **未验证型** | 标"未验证"，不假装看过 |
| 来源冲突 | **待确认型** | 列冲突双方，等裁决 |
| 数据缺失 | **缺口型** | 标缺口 + 补全路径 |
| 推断内容 | **假设型** | 明标"这是推断" |
| 能力未测 | **未测型** | 标"未实测"，不写"可用" |

## 反例与坑

- **猜一个填上** → 污染结论，比空着更糟。
- **笼统说"有风险"** → 无法行动。
- **把模板写成模型** → 下游当真。
- **有未知就全停** → 过度保守，交付不了。
- **未知不标归属** → 永远没人补。
- **边界**：无。这是全类通用纪律。

## 与卡 12 的区别（容易混）

| | 卡 12 证据升级拒绝 | **卡 16 未知标注** |
|---|---|---|
| 前提 | **知道**，但不许说成更高等级 | **不知道**，必须承认 |
| 动作 | 拒绝升级（A ≠ B） | 标注缺口（标"待验证"） |
| 例 | `已安装 ≠ 已认证` | `平台 URL 待确认` |

**一句话**：卡 12 管"别吹"，卡 16 管"别装"。

## 案例（抽象）

- 榜单数据：一个模型条目无法核实 → 标待确认，不进榜单。
- 生产环境：拿不到 SSH → 标"未在主机验证"，但把配置纳入仓库继续推进。
- 数据建模：字段并集未定 → 暂不生成产物，先出计划。
- 平台资料：URL 待确认 → 条目保留但标状态。

## 复现门（P2）

- **方法**：第二个模型（Sonnet）读 20 会话样本（`_raw/sample-unknown.md`），独立抽取。
- **结果**：**通过，带一处重要修正。**
- **核心主张证实**：显式标注 **11/20**（严格标记 7/20）· **移出产物 9/20** · **仍交付可验证部分 18/20** · 不伪装 8/20。
- **跨类型证实**：横跨审计诊断、数据迁移、部署运维、安装规划、产品研究、述职报告 **6 种**。
- **修正（关键）**：**标注 ≠ 移出**。标注 11/20，但真正把未知从产物里剔除只有 9/20。独立模型指出承重槽是"**未知被移出产物，而不只是脚注**"。本卡已把 U4 标为承重步。
- **增量**：补入 U0 先建基线、U5 仍交付可验证部分（18/20，最强）、U6 给出补全路径。
- **修正 ②**：U5（仍交付）比 U2/U4 都强，说明纪律的核心不是"停"，是"**标了但继续走**"。
- **裁决**：PASS（带修正）。置信级 **高**。

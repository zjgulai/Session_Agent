# 经验卡 · 状态继承（provenance-aware 重算）

- **身份**：Agent 全栈 / 产品经理
- **问题类**：自动流程重跑时，怎么不把"别人产出的状态"冲掉
- **support**：出现在 **432/2,787 = 16%** 会话中
- **置信级**：中（16% 覆盖 + 两个项目复盘交叉验证；但样本经策展，计数为下限）
- **脚手架判定**：**部分**。技能 `principle-make-operations-idempotent` 规定了**幂等**（重复执行收敛到同一状态），但**没有**规定"状态来源感知"。
  **关键区分（复现门确认）**：幂等只保证"自己产出的状态"收敛；一个完全幂等的流程**仍可能**覆盖人工审批、用户未提交改动、历史快照——因为这些都不在流程自己的输出集合里。
- **口径**：全量

## 场景

有个自动化流程（脚本 / 生成 / 重建 / 采集 / 迁移），会重复运行。运行期间，**别人**（人或上游）已经产出了状态。

## 问题

- 脚本重建 → 人工选好的被打回 pending
- 一次失败 → 之前成功的结果被清空
- 重做 → 基于上一轮失败输出，误差累积
- 自动覆盖 → 用户未提交的改动被冲掉
- 重新生成 → 历史结论被改写

## 解决方案（收敛解）

**只重算"自己产出的状态"；其他来源的状态只继承，不重算。**

这条不变量叫 **provenance-aware（状态来源感知）**：
- 流程自己生成的 → 可以重算
- 人判断的 → 继承
- 用户工作树的 → 不碰
- 其他仓库的 → 不碰
- 历史产出的 → 标记，不删除

## SOP（每步带独立 support）

| 步 | 动作 | support | 触发 | 决策点 |
|---|---|---:|---|---|
| S1 | **限定爆炸半径**：先说明"不会碰什么" | 10/20 | 动手前 | 说不清 → 先别动 |
| S2 | **区分状态来源**：自产 / 人判断 / 用户工作树 / 历史 / 其他仓库 | 复现门补入 | 每次重算前 | 分不清 → 保守当外部，不重算 |
| S3 | **人工字段继承**：读取现有值，只补差异 | 3–4/20 | 有审批/选中/备注 | 重算 → 人工白做 |
| S4 | **默认追加，不替换** | 6/20 | 新建产物 | 替换 → 历史丢失 |
| S5 | **必须改时：最小合并**，只改出问题的那一处 | 5/20 | 非改不可 | 整体重写 → 覆盖 |
| S6 | **写前备份** | 4/20 | 有覆盖风险 | 无备份 → 不可逆 |
| S7 | **失败只追加，不清空**已有成功 | 7/20 | 有失败时 | 清空 → 前功尽弃 |
| S8 | **重做从原始输入**，不用失败输出 | 7/20 | 返工时 | 基于失败迭代 → 污染累积 |
| S9 | **不回滚未提交改动**，只报告 | 4/20 | 有脏工作区 | 回滚 → 丢工作 |
| S10 | **历史标记而非删除** | 5/20 | 有被取代的产物 | 删除 → 无法回溯 |

## 指令形状

```
只重算 {自产状态}；{人工/历史/其他仓库} 的状态只继承，不重算。
默认追加，不替换；必须改时只改 {最小范围}，改前备份。
失败只记录错误，不清空 {已有成功}。
重做从 {原始输入} 重新开始，不基于 {失败输出} 继续。
```

**关键句**：`只重算 {自产状态}，其余继承`。缺了它，流程会用"幂等"为名把人做的判断重算掉。

## 判断状态来源（核心动作）

| 来源 | 处理 |
|---|---|
| 本流程上次产出 | ✅ 可重算 |
| 人审批/选中/标注 | ❌ 继承 |
| 用户未提交工作树 | ❌ 不碰 |
| 其他仓库/外部系统 | ❌ 不碰 |
| 历史快照/旧结论 | ❌ 标记为历史，不删除 |
| 原始输入 | ✅ 可重新读取（重做的基准） |

## 真实例句（抽象化）

- `selected_outputs 这些人工审计字段必须继承，避免下一次脚本重建把已完成候选又打回 pending`
- `失败 run 只能记录错误，不能清空已有成功 top papers`
- `重做永远回到原人物照、物件照和主题母版，不让上一轮生成图继续污染身份`
- `写成新的计划文件，不覆盖旧快照里的计划`
- `不会重写历史文档本身的旧结论，只是给它们加上强边界`
- `保留原有叙事、数据与来源，只修正容器、资产引用与字段合同`
- `保留现有工作区改动，只新增隔离产物`

## 反例与坑

- **用"幂等"当借口重算一切** → 人工判断被覆盖（幂等只保证收敛，不保证保留外部状态）。
- **重建从零开始** → 人工字段全丢。
- **失败清空结果** → 一次错误毁掉几小时工作。
- **基于失败输出重做** → 误差递归累积（生成式任务尤其致命）。
- **自动回滚脏工作区** → 用户没提交的改动消失。
- **删除被取代的产物** → 无法回溯。
- **边界**：纯一次性任务、无外部状态介入时，不适用。

## 与卡 17 的区别（容易混）

| | 卡 17 默认拒绝 | **卡 19 状态继承** |
|---|---|---|
| 管什么 | **能不能放行** | **重算时保留什么** |
| 方向 | 阻断 | 继承 |
| 例 | 条件不全就不发布 | 人工选中不能被打回 |

**一句话**：卡 17 管"别放进来"，卡 19 管"别冲掉"。

## 与"幂等"的关系（复现门确认）

```
幂等 ⊂ 状态继承
```

- 幂等：`f(f(x)) = f(x)` —— 只对自己产出的状态保证收敛
- 状态继承：`f` 不能重算**非自己产出**的状态

**一个完全幂等的流程，仍可能覆盖人工审批、用户改动、历史快照。**
所以幂等是必要不充分条件。

## 两个项目复盘交叉验证

| 问题 | 写真项目 | 知识库项目 |
|---|---|---|
| 人工成果被覆盖 | 被编辑成片不能升级为身份参考 | 人工审计字段必须继承 |
| 失败污染 | 重做回原始素材 | 失败 run 不清空成功 |

**统一原则**：自动流程可以重跑，但不能重算外部来源的状态，也不能让失败污染成功。

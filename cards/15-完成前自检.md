> **本卡是跨类纪律。** 技能文本里 `自检/self-check` 出现 **0 次**、`复核/re-review` **0 次**——但会话里覆盖 **42%**（1,175/2,794）。这是纯涌现。

- **类型**：跨类纪律
- **身份**：跨三岗
- **support**：出现在 **1,175/2,794 = 42%** 会话中
- **置信级**：**高**（42% 覆盖 + 技能文本零规定）
- **脚手架判定**：**涌现**。技能文本 95 个文件中，`自检`/`self-check`/`复核`/`re-review`/`复盘` 均为 0 次
- **口径**：全量

## 场景

东西做完了，准备交付。最容易出错的时刻——不是做错，是**做漏**。

## 问题

- 做完了就交 → 漏项、占位符、数字对不上。
- 交给用户去发现 → 信任成本高，返工。
- 全文重读 → 太慢，且看不出"一致性"问题。

## 解决方案（收敛解）

**交付前做最后一轮定向自检：核对一致性，不是重读全文。**

核心：**自检查的是"对得上吗"，不是"写得好吗"。**

## SOP（每步带独立 support）

| 步 | 动作 | support | 触发 | 决策点 |
|---|---|---:|---|---|
| C1 | **限定自检范围**：只查本次产出，不重读全文 | 边界 87% | 总是 | 范围过大 → 拆成清单 |
| C2 | **核对证据数字**：文中数字与证据源一一对应 | 证据 76% | 有数字时 | 对不上 → 修或删 |
| C3 | **核对一致性**：文档 vs 实现、声明 vs 实际 | 一致 67% | 总是 | 不一致 → 以实际为准 |
| C4 | **核对结构完整性**：章节齐吗、链接通吗、格式对吗 | 结构 55% · 链接 365 | 有文档时 | 断链 → 修 |
| C5 | **找占位符与遗漏**：TODO / TBD / "待补充" / 空章节 | 缺口 44% | 总是 | 发现 → 当场清 |
| C6 | **找重复**：同一内容出现两次、术语不一致 | 重复 48% | 有长文时 | 重复 → 合并 |
| C7 | **清理自检中发现的问题**，不留给用户 | 总是 | 发现问题时 | 只报告不修 → 不合格 |
| C8 | **报告自检结果**：查了什么、发现什么、修了什么 | 总是 | 总是 | 不报告 → 用户不知 |

## 指令形状

```
我正在做最后一轮自检：核对 {证据数字}、{结构完整性}、{一一对应}，
并清理 {占位符 / 会让执行者误解的表述}。
```

典型实例（来自真实会话，已抽象）：
- `我正在做最后一轮计划自检：核对证据数字、Markdown 完整性、测试覆盖与实施任务的一一对应，并清理计划里会让执行者误解为占位符的表达。`
- `最后验证会重新核对四个关键证据数字、确认计划没有占位项、Markdown 结构完整。`
- `轻量复核：确认当前文件状态、已有公共模块形态、脚本入口，避免覆盖你工作区里已有资产。`

**关键句**：`核对 {一致性}`，不是 `再读一遍`。**自检查的是对得上吗。**

## 条件变体

| 条件 | 变体 | 差别 |
|---|---|---|
| 有数字/指标 | **对账型** | 数字与证据源逐一对应 |
| 有文档 | **结构型** | 章节齐、链接通、格式对 |
| 有实现 | **一致型** | 文档 vs 实现 |
| 长文/报告 | **去重型** | 找重复与术语不一致 |
| 代码变更 | **完整型** | diff 有无遗漏文件 |
| **任务是只读评审** | **只报不修** | 评审禁止改文件 → 只报告，这是分支不是反例 |
| **已提交** | **提交后重跑** | 证据要落在最终 SHA 上 |
| 自检本身有副作用 | **清理痕迹** | 清缓存/临时产物，不留痕 |

## 反例与坑

- **自检 = 重读全文** → 太慢，且看不出一致性。
- **只报告不修** → 把问题留给用户。
- **不限定范围** → 自检变成第二次开发。
- **只查格式不查一致性** → 文档漂亮但和实现对不上。
- **自检后不报告** → 用户不知道你查过。
- **边界**：极小改动（一行）不需要完整自检。

## 案例（抽象）

- 计划文档交付前：核对证据数字、Markdown 完整性、测试覆盖与任务一一对应，清理占位符。
- 部署后：逐字节验收 184 个 agent 与部署副本完全一致。
- 移植前：轻量复核当前文件状态与脚本入口，避免覆盖已有资产。
- 视觉验证后：临时切到移动视口复核，最后重置视口。
